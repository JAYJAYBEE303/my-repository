--- layout: default title_suffix: Wiki — Josh Bailey page_wide: true scroll_gate: false --- {%- comment -%} ============================================================================= wiki-entry.html — the shell around one SECTION of a write-up, at /projects/wiki//
/. Nests inside _layouts/default.html, so the header, nav, search, footer, theme toggle, paper grain, type scale and reveal animations all come from the main site with nothing restated here. `title_suffix` above is THIS LAYOUT's own front matter, not a section's — Jekyll exposes it to the parent layout as `layout.*`, so default.html's can read it once here instead of every section page restating `Wiki — Josh Bailey` in its own front matter. Matches the qualified form _layouts/wiki-app.html builds directly for the app page's <title>. `page_wide` works the same way. The site's default container is sized for a single column of prose; this layout puts two rails either side of that column, which leaves the prose far too narrow inside it. The flag widens the container for wiki entries only — every other page keeps the prose width it was designed around. `scroll_gate: false` too — a wiki section is straight into reference content the moment it loads (crumb, title, lede), same as /projects/. There's no hero to hold the body back for. Front matter a section page declares: layout: wiki-entry (required) parent: gaffer-iq (required — the app's slug) slug: calculations (globally unique across the wiki) order: 80 (sort position within the app) group: Matchups (rail heading) title: Calculations lede: one italic sentence (optional) shape: list of {group, terms} for this section's own infobox (optional — see _includes/wiki-infobox.html. Terms are glossary keys; one with no entry renders as plain text) revised and status are NOT declared per section. They are read from the parent app, so twelve pages do not restate the same two values. A section may still override either of them. The meta strip used to carry an Author line, inherited the same way. It said "Josh Bailey" on every page of a personal site — a field that never varies is not metadata. It now reports read time, which does vary and is the thing a reader actually wants before starting. `kind` is still inherited the same way, but this layout no longer shows it: every section of an app carries the same one, so the meta strip repeated `Application` on all twelve pages and said nothing. Nothing else reads it now either — /projects/wiki/ used to, and is a redirect to /projects/ as of this change. `kind`, `group`, `summary` and `author` are all in that position now: left in the app front matter rather than deleted, because they are true and an index that wants them again should not have to re-derive them. Everything derived below — the rail, numbering, backlinks, pager, Entry status — is read from the section pages themselves at build time. There is no second manifest. Two markup conventions are available in a section's body and are compiled at build time: the double-square-bracket internal wiki link and the double-parenthesis footnote.
